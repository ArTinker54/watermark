# Персональная раздача уроков с невидимой меткой

Обучающие материалы раздаются не в общем канале, а лично каждому участнику
через Telegram-бота. В каждую картинку вшивается невидимая метка с номером
участника и номером урока. Если материал утёк — по метке на утёкшей картинке
(в том числе со скриншота) определяется конкретный человек.

Один репозиторий, два бота, общая база и общий движок метки.

```
                    admin-bot                     student-bot
                 (только автор)                  (все ученики)
                        │                              │
        /newlesson ─────┤                              ├───── /start → оферта → uid
        /trace ─────────┤                              │
        /stats ─────────┤                              │
                        │                              │
                        ├──── рассылка меченых ───────►│
                        │     копий (токен student)    │
                        ▼                              ▼
                 ┌──────────────────────────────────────────┐
                 │  SQLite  +  storage/  +  watermark engine │
                 └──────────────────────────────────────────┘
```

## Как это работает

1. Автор шлёт урок (текст + картинки) в **admin-bot**. Бот сохраняет
   **пристинный оригинал** — без метки. Он нужен потом, чтобы выровнять
   утёкшую картинку по геометрии.
2. Для каждого ученика генерируется своя копия с меткой `V|{uid}|{lesson_id}`
   и уходит ему в личку **токеном student-bot** (у admin-бота нет права писать
   ученикам).
3. Утёкший скриншот присылают в `/trace`. Система ищет на нём область урока
   (template match по всем сохранённым оригиналам), выравнивает найденный кроп
   к геометрии оригинала и извлекает метку.

## Быстрый старт

### Docker (боевой вариант)

```bash
cp .env.example .env
```

Заполните `.env` (два токена, свой Telegram ID, два пароля метки), затем:

```bash
docker compose up -d --build
```

Логи:

```bash
docker compose logs -f admin-bot
```

База и картинки живут в томе `bot-data`, поэтому переживают пересборку образа.

### Railway (или любой хостинг с одним сервисом)

Том Railway монтируется ровно к одному сервису, а базу и пристинные оригиналы
уроков боты обязаны делить: без оригиналов не работает трассировка. Поэтому там
запускается один сервис с обоими ботами в одном процессе:

```bash
python -m app.bots.combined
```

Это уже прописано в [railway.toml](railway.toml). В настройках сервиса нужно
примонтировать том в `/data` и задать переменные из `.env.example`.

### Локально

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
pip install --no-deps -r requirements-wm.txt
```

`--no-deps` для второго файла обязателен: `blind-watermark` объявляет
зависимость на `opencv-python` (сборку с GUI), а нужен `opencv-python-headless`.
Обе сборки кладут пакет `cv2` в одно место и конфликтуют.

Запуск двумя процессами:

```bash
python -m app.bots.student
```

```bash
python -m app.bots.admin
```

Либо одним, если так удобнее:

```bash
python -m app.bots.combined
```

Два процесса предпочтительнее там, где это возможно: падение одного бота не
уносит второй.

## Настройка

Всё через `.env`, полный список — в [.env.example](.env.example).

| Переменная | Что это |
| --- | --- |
| `ADMIN_BOT_TOKEN`, `STUDENT_BOT_TOKEN` | Токены двух ботов из @BotFather |
| `ADMIN_IDS` | Telegram user_id автора(ов) через запятую |
| `WM_PW_IMG`, `WM_PW_WM` | Пароли метки, целые числа `0..4294967295` |
| `VSA_GROUP_ID` | Опционально: проверять членство в группе при регистрации |
| `DB_PATH`, `STORAGE_PATH` | Пути к базе и хранилищу |
| `OFFER_PATH` | Файл с текстом оферты |

**Пароли метки нельзя менять после первой рассылки.** Со сменой пароля метка на
всех ранее выданных картинках перестанет читаться, и трассировка станет
невозможна. Храните копию отдельно от сервера.

Если задан `VSA_GROUP_ID`, а бот не добавлен в группу, регистрация будет
отклоняться с сообщением об ошибке проверки — это намеренно: молча пускать всех
подряд при сломанной проверке хуже, чем не пускать никого.

## Команды

**admin-bot** (whitelist по `ADMIN_IDS`, чужие запросы игнорируются молча):

| Команда | Что делает |
| --- | --- |
| `/newlesson` | Собрать урок, показать превью и разослать персональные копии |
| `/trace` | Прислать утёкшую картинку или скриншот → uid и личность |
| `/stats` | Ученики, уроки, доставки, трассировки |
| `/cancel` | Прервать текущий сценарий |

Картинку можно прислать и без команды — бот сразу начнёт трассировку.

**student-bot:**

| Команда | Что делает |
| --- | --- |
| `/start` | Регистрация: оферта → «Принимаю» → присвоение uid |
| `/id` | Свой номер участника |
| `/offer` | Текст условий |
| `/help` | Справка |

Уроки приходят автоматически.

### Онбординг действующих участников

Telegram не даёт боту написать первым тому, кто не нажал Start, — поэтому
регистрация только pull-овая. Действующие участники заходят тем же путём:
нажимают `/start` в student-боте и принимают оферту. Без принятого согласия
ученик не попадает в список получателей вообще.

## Формат метки

```
V|{uid:04d}|{lesson_id:05d}     например  V|0042|00001
```

Длина фиксирована — 12 символов, 95 бит. Именно поэтому `wm_shape` при
извлечении известен заранее и его не надо хранить рядом с каждой доставкой.
Значение вычисляется из формата в [`app/watermark/payload.py`](app/watermark/payload.py),
а не захардкожено, — разойтись с реальностью оно не может.

## Устойчивость метки

Проверено тестами (`tests/test_watermark.py`):

| Воздействие | Результат |
| --- | --- |
| JPEG 90 / 75 / 50 | читается |
| Даунскейл до 0.75 / 0.5 | читается |
| jpeg80 → jpeg75 → скрин 0.5 → jpeg90 | читается |
| Скриншот всего экрана, урок занимает часть кадра | читается (область находится сама) |
| JPEG 30 | не читается — осознанная граница MVP |
| Сильная обрезка без восстановления геометрии | не читается |

Ниже масштаба ~0.5 результат становится неустойчивым и зависит от того, как
легла сетка JPEG. В этом случае система честно отвечает «метка не читается».

## Почему ложное опознание невозможно

Извлечение из неточного кропа умеет возвращать **частично** верную строку:
например `V|0042|00401` вместо `V|0042|00001`. Формат она проходит — и назвала
бы чужой урок. Поэтому результат принимается только при совпадении трёх условий:

1. строка соответствует формату метки;
2. `lesson_id` из метки равен id урока, оригинал которого найден на картинке;
3. `uid` принадлежит существующему ученику.

Дополнительно сверяется журнал доставок: этому ученику этот урок правда
выдавался. Если сходится не всё — ответ «метку прочитать не удалось», без
догадок. Проверка закреплена тестом `test_partial_extraction_is_rejected`.

## Данные

```
data/
  db.sqlite3
  storage/
    lessons/<lesson_id>/orig_0.png   пристинный оригинал, БЕЗ метки
    marked/<lesson_id>/<uid>_0.png   персональная меченая копия
    traces/<stamp>_<id>.png          что присылали на трассировку
```

Таблицы: `students`, `lessons`, `lesson_images`, `deliveries`, `trace_attempts`.
Схема создаётся автоматически при старте (`create_all`, идемпотентно).

Ключевое, что нужно бэкапить: `db.sqlite3`, папка `lessons/` и пароли метки.
Без оригиналов урока трассировка не работает — по ним ищется область на скрине.
Папку `marked/` можно не бэкапить: копии восстанавливаются повторной генерацией.

`uid` присваивается один раз и не меняется никогда — он уже вшит в разосланные
картинки. Повторный `/start` uid не сбрасывает.

## Оферта

Текст лежит в [`app/texts/offer.txt`](app/texts/offer.txt) и читается с диска при
каждом показе — правка видна сразу, пересборка образа не нужна (в compose файл
примонтирован в контейнер). Разметка — HTML-подмножество Telegram: `<b>`, `<i>`,
`<u>`, `<a href>`, `<code>`.

**Текущий текст — рабочий черновик, финализировать его должен юрист.**

## Тесты

```bash
pip install -r requirements-dev.txt
pytest -q
```

Что покрыто:

- `test_payload.py` — формат метки, постоянство длины, отбраковка мусора;
- `test_watermark.py` — embed → атака → extract на цепочке сжатия и скриншота,
  визуальная идентичность (PSNR > 35 дБ), чужой пароль не читает метку;
- `test_flow.py` — сквозной сценарий: регистрация → урок → рассылка →
  скриншот утечки → трассировка до конкретного ученика.

## Версии зависимостей

Пины жёсткие и подобраны под Python 3.11: `numpy` и `PyWavelets` новее
указанных под 3.11 колёс не имеют. Версию `blind-watermark` менять нельзя —
библиотека требует совпадения версии при встраивании и извлечении.

Совместимость между версиями `numpy` держится на `np.random.RandomState`:
это legacy-генератор с зафиксированной последовательностью, поэтому пароли
работают одинаково на любой numpy 2.x.

## Ограничения MVP

- Формат метки вмещает 9999 учеников и 99999 уроков.
- Состояние сценария `/newlesson` хранится в памяти процесса: перезапуск
  admin-бота во время сборки урока потеряет черновик (файлы останутся в
  `storage/staging/`).
- Рассылка идёт в том же процессе, что и бот. На полсотни учеников это секунды;
  на тысячах имеет смысл вынести её в отдельного воркера.
- Восстановление геометрии при сильной обрезке (пират вырезал часть графика)
  не реализовано.
